## Purpose

missing sub-task: a constructed nonlinguistic control, independently designed (not simply adopting
Raghavendra's SIGIL), for the first preregistered SQ-3 test. This document specifies the control's

select, exactly as the parent preregistration's own "Next steps" require.

## Design principle: compositional meaning without phonological value

Per FSW's own framing (directly read, `config/sidequests.md`) and SIGIL's existence proof, a
nonlinguistic control must plausibly carry *some* kind of meaning — otherwise it isn't a fair
alternative to full linguistic writing, just noise. The mechanism below generates sequences from a
fixed, small **attribute grammar**: each "inscription" records a fixed number of independent
categorical attributes (e.g., for an accounting/tally-like system: commodity-class, quantity-band,
transaction-type, location-class), and each attribute has its own dedicated sign or sign-group. This
is a real, historically-attested pattern for tally/administrative sign systems (comparable to how the
sibling Voynich project's own constructed nulls are engineered rather than historically derived, and
disclosed as such) — not proposed here as a specific historical Indus-adjacent system, just a
structurally plausible nonlinguistic alternative.

### Generative rule (mechanism, seed-agnostic — exact parameters filled in once SQ-1/SQ-2 resolve)

1. Fix `k` independent attribute slots (k to be set once SQ-2's real sign-inventory size is known;
   a reasonable placeholder is k=3–4, matching short inscriptions' own ~5-sign average brevity).
2. Each attribute slot has its own closed sign alphabet (disjoint from the other slots' alphabets —
   this is what makes the system "compositional": a sign's identity alone tells you which attribute
   it encodes, independent of position).
3. An "inscription" is generated by independently sampling one sign from each of the k slots'
   alphabets (order of slots within an inscription may be fixed or lightly randomized — both variants
   should be tested, since Indus's own directional-asymmetry statistics are one of the things SIGIL's
   own abstract claims to reproduce).
4. Marginal sampling frequencies per slot are calibrated to Zipfian-like skew (matching the general
   shape of short-text sign-frequency distributions observed across many real systems, linguistic and
   non-linguistic alike) — not calibrated to match the Indus corpus's own frequencies directly, which
   would make the control's success circular.
5. No cross-slot dependency is built in by default (a genuinely non-linguistic combinatorial system);
   a second variant with weak cross-slot dependency (e.g. certain quantity-bands co-occurring more
   often with certain commodity-classes, an ordinary real-world accounting correlation) should also be
   tested, since real administrative systems do have such correlations without being language.

## What this does and does not do

This specifies the control's *generative logic* only. It does **not** yet fix: k's exact value, the
per-slot alphabet sizes, the marginal frequency shape's exact parameters, or the specific statistic X
from the parent preregistration that this control will be compared against — all of which depend on
SQ-1/SQ-2's still-unresolved corpus and sign-inventory selection, per the parent document's own
sequencing. It is disclosed, per this project's own discipline, as an engineered mechanism built for
this test — not a claim about any real historical Indus-adjacent accounting system, and not adopting
SIGIL's own specific implementation (which remains Raghavendra's tool, not reproduced here).
